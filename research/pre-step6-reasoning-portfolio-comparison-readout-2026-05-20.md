## Summary

The first local portfolio slice is structurally viable:

- `problem_state.v1` fixtures describe the problem without solving it.
- `candidate_inventory.v1` preserves existing engineered artifacts and
  expansion refs.
- `reasoning_affordance.v1` records preserve source grounding, risks,
  protected slots, and cheap Step 6 tests.
- `step6_attention_map.v1` gives Step 6 a compact active surface, an edge
  reserve, weak/negative-space receipts, parked receipts, and archive refs.

The early comparison signal is promising for high-clutter cases and useful as a
negative-control discipline, but not enough to change default runtime behavior.

The added portfolio map preserves counsel-incentive testing, the Wednesday
protocol, channel distinction, and the parked leverage false friend. The blind

reproduces the previous best.

## Falsifiers To Keep Live

- If Step 6 over-explains every reserve item, the portfolio still creates
  answer bloat.
- If the compact map loses why a pressure mattered, raw/hybrid may remain
  better.
- If negative-control cases get extra active pressure only because a map
  exists, the design is too eager.
- If provider-generated affordance calls do not beat deterministic baseline
  conversion, the extra cognition is not justified.

## Recommendation

replays using the rendered attention maps and compare actual revised answers

### Updated Understanding

Bevelin is useful as a private enrichment probe, not as a new architecture.
The value came from targeted cognitive lenses:

- incentives and feedback loops;
- denominator and false-precision caution;
- commitment and authority pressure;
- inversion and fallback disappearance;
- absence-of-evidence discipline;
- opportunity-cost and middle-path preservation.

The best pattern is:

```text
attention map -> lens probe -> lens answer core -> comparison gate
```

The lens probe may mark material as `active`, `scan`, or `parked`, but it must
not decide the final answer. The comparison gate must allow four outcomes:

- `lens_improves`: expand replay;
- `lens_boundary_case`: preserve the learning but stand down or retest;
- `lens_retest`: no clear signal yet;
- `lens_discard`: the lens adds bloat, abstraction, or over-control.

This is the non-castrating shape: the system preserves broad optionality and
off-frame receipts, but it does not automatically stuff every lens result into
Step 6.

No `SKILL.md` update or runtime wiring is justified yet. The next best
experiment is one more replay-style comparison for founder and PhD v2 using
the Bevelin-enhanced answer cores, followed by a separate Polya problem-shape
lens so we can see whether the lens-pack interface generalizes.

## Cognitive Gate Addendum

The comparison gate is not a deterministic quality judge.

The deterministic system does not decide whether a lens improved Step 6. It
hosts and constrains a cognitive judgment. In the current local research slice,
that cognitive judgment is recorded as `human_static_research_judgment`. In a
future manual/live slice, the same field could be filled by a small targeted
LLM reviewer call.

The split is:

```text
cognition judges quality
code validates custody and prevents promotion mistakes
```

The cognitive reviewer sees the relevant candidates and asks:

- did the answer become more useful?
- did the lens preserve an edge Step 6 might otherwise miss?
- did it reduce or increase public cognitive load?
- did it keep breadth and optionality alive?
- did it stand down on negative controls?

The deterministic validator checks:

- source refs exist and match;
- attention-map render hashes match;
- answer cores and comparison records validate;
- expected inclusions and exclusions are respected;
- public answers do not leak private machinery;
- runtime wiring and `SKILL.md` promotion remain blocked.

This matters because a dumb deterministic gate would reward the wrong things:
more criteria wins, more labels, more source refs, or more active items. Those
are not quality. The gate must preserve the judgment question:

```text
Did this extra context help Step 6 think better without doing Step 6's job?
```

### Design Result

The card deck is better aligned with the product philosophy than a selector:

```text
deterministic code packages and validates
Step 6 judges cognitive usefulness
```

The deck contains:

- the clean hybrid card as the concrete anchor;
- a Bevelin card for incentive, inversion, false precision, denominator, and
  commitment pressure;
- a Polya card for problem shape, knowns/unknowns, next informative move, and
  sequencing;
- a problem read so Step 6 has the actual case, not only prior answer text;
- source refs and private receipts;
- a deterministic-limit statement saying code does not decide cognitive
  usefulness.

The comparison gate had one important bug in its first live attempt: the
reviewer was blinded but still asked to report `deck_effect`. That is
impossible to do reliably because the reviewer does not know which blind label
is the deck. The corrected gate now asks the cognitive reviewer only for
A/B/tie quality judgment. Deterministic code privately maps the blind winner
to `improves`, `regresses`, or `equivalent` and rejects inconsistent artifacts.

### Refined Prompt Result

The first replay prompt over-emphasized concision and sometimes compressed
away concrete distinctions. The prompt was tightened to preserve the user's
value:

```text
as short as possible, but no shorter
do not compress away tripwires, conditions, actor-specific steps, or
irreversible-risk distinctions merely to be concise
the clean hybrid anchor can remain the visible backbone
```

### Current Interpretation

This is the strongest evidence so far for the broad private card deck as the
next research shape. It is not runtime evidence yet. It says:

1. Do not reduce pre-Step-6 to a deterministic usefulness selector.
2. Do give Step 6 a broad but labeled private deck: anchor plus lens cards.
3. Require Step 6 to keep a private consideration ledger.
4. Use cognitive comparison gates for research iteration.
5. Let deterministic code validate custody, blinding, public hygiene, and

6. Keep the mother case as a live falsifier: sensitive safety contexts punish

Recommendation remains research-only. The next experiment should retest the

## Novelty-Ledger And Anchor-Preservation Addendum

We continued the card-deck loop because the first pass still had two important
failure modes:

- Step 6 sometimes treated confirming support as visible additive pressure,
  creating mild public bloat.
- Step 6 sometimes compressed away concrete anchor payload while trying to be
  concise.

Changes made:

- Added `novelty_role` to every private card-consideration ledger item:
  `visible_backbone`, `additive_pressure`, `confirming_support`, or
  `private_guardrail`.
- Added the prompt rule that the ledger is where card consideration lives; the
  public answer should not grow just to prove every card was considered.
- Added sensitive safety/legal discipline: visible enrichment must add a
  concrete safeguard, tripwire, or channel distinction; otherwise keep it
  private.
- Added anchor-payload preservation: do not shorten by deleting named channels
  or resources, communication boundaries, dated windows, gates, actor sequence,
  tripwires, or evidence checks.
- Added a public hygiene reminder after a founder replay correctly failed
  validation for leaking forbidden public terms (`bundle`, `lane`).
