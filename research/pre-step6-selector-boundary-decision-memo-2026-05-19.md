## Question

What evidence would justify even specifying a tiny off-default rendered-handoff
generator later?

The answer is not "we have four wins and two stops, so build." The
negative/control stops changed the problem:

```text
rendered hybrid can be valid, grounded, and still not useful enough to count
```

So the next question is:

```text
when should the system decline to generate or use the rendered surface at all?
```

This memo is a selector-boundary decision artifact. It is not an implementation
plan.


## What Rendered Improves

Rendered hybrid appears most useful when the final answer would otherwise lose a
specific pressure that matters to the decision.

Observed improvement patterns:

```text
preserves unresolved two-sided conflict
keeps risk-if-ignored visible without making it a verdict
demotes duplicate or misfit pressure without deleting custody
preserves a quiet caution in plain language
reduces raw-only leakage of demoted machinery
keeps source/overclaim checks attached to the candidate
```

Good examples:

```text
PhD conflict:
  rendered preserved Silva-vs-fallback tension and evidence gates

Mother quiet:
  rendered preserved monitored-channel caution without pressure-card machinery

Founder high-clutter:
  rendered preserved dependency-system pressure and kept quiet receipts quiet
```

The safe claim:

```text
rendered can transport selected private pressure into Step-6-style answer cores
while preserving custody
```

The unsafe claim:

```text
rendered is generally better
```

## What Rendered Costs

The repeated cost is not hallucination. The repeated cost is answer feel.

Observed costs:

```text
medium naturalness debt in five of six audited rendered answers
more visible structure than control/raw
possible source-grounding stretch through extra advisory framing
possible answer bloat in high-clutter cases
procedural texture in counsel-first or expert-first cases
temptation to treat valid nuance as public instruction
```

The consultant negative/control replay and native rejudge are the cleanest
warning:

```text
rendered passed source/overclaim audit twice
rendered preserved useful decision nuance
control still won both aggregate comparisons
both replay decisions were stop
```

That means the selector cannot ask only:

```text
is rendered safe?
```

It must also ask:

```text
does rendered add enough decision value to pay for its naturalness and burden tax?
```

## Consider Conditions

Rendered handoff generation should be considered only when there is a visible
risk that simpler inputs will lose or misuse selected pressure.

Consider rendered when:

```text
control drops a live risk-if-ignored
case has unresolved two-sided conflict
case has high clutter where duplicate/misfit pressure must be demoted
case has a quiet sentinel caution that must survive in plain language
raw-only carries useful pressure but leaks demoted machinery
raw-only is too broad and risks overusing every valid artifact
there is a known source/overclaim risk that needs explicit custody
rendered can preserve pressure while reducing private residue
```

These are admission questions, not scoring rules:

```text
What pressure would likely be lost without rendered?
What would go wrong if that pressure were forced?
What would go wrong if that pressure were ignored?
What is the smallest rendered surface that could carry it?
What would make control/raw enough?
```

## Decline Conditions

Rendered handoff generation should decline when the simpler answer path is
already doing the job.

Decline rendered when:

```text
control is already short, grounded, and humane
the needed pressure is already carried by counsel-first, therapist-first, expert-first, or safety-first restraint
no strong missing pressure is observed
raw/rendered mainly add protocol, channel, or process detail
rendered loses or ties on source grounding, overclaim risk, lightness, and unforcedness
naturalness debt is medium without clear decision-quality gain
private pressure would make the answer feel more procedural than wiser
the case needs calm first steps more than richer reasoning pressure
```

The consultant negative/control case is the model:

```text
control already gave the safe first move
rendered added valid nuance
valid nuance increased burden
control won aggregate
rendered audit passed but does_not_count
```

The selector boundary should preserve that outcome as a success, not a failure.

## Missing Evidence Before Implementation Discussion

Generator implementation is still not earned. A docs-only generator boundary
proposal is now allowed only as a containment artifact after the native
consultant rejudge confirmed that rendered decline is sometimes correct.

Before even specifying a tiny off-default generator boundary, we needed at
least one of:

```text
a second negative/control replay, preferably native or less-author-biased
a native rejudge of the consultant negative/control stop
a selector-boundary replay where the expected decision is "decline rendered"
and the evidence record confirms that decline
```

The native consultant rejudge now satisfies the second condition. It does not
authorize implementation. It only authorizes a docs-only proposal that defines
what a future generator must refuse to do before implementation can be
discussed.

We also need a clearer answer to:

```text
Can a future generator produce no rendered handoff without treating that as an error?
Can it leave a receipt for declining without adding private pressure?
Can it avoid turning decline into a deterministic verdict?
Can it keep medium naturalness debt as a design constraint rather than a score?
```

Current blocker:

```text
we have native-confirmed evidence that decline is sometimes correct
we do not yet have evidence that a generator/selective process can find decline cases
```

## Product Boundary

The future selector, if it is ever designed, must not decide final truth.

Allowed selector responsibilities:

```text
notice candidate pressure surfaces
package candidate rendered handoffs for off-default evaluation
decline generation when simpler control/raw is likely enough
record why it declined
validate refs, caps, modes, and source custody
keep runtime/product promotion blocked by default
```

Forbidden selector responsibilities:

```text
decide final advice
decide which pressure is true
force Step 6 to use rendered pressure
turn medium naturalness debt into a numerical formula
convert a valid nuance into a public obligation
promote generated handoffs into runtime behavior
```

The doctrine remains:

```text
deterministic code keeps custody
the LLM performs judgment
valid pressure is still rejectable
```

## PM Verdict

The project has matured from:

```text
can rendered transport pressure?
```

to:

```text
can we know when not to transport it?
```

That is the right problem.

The selector boundary is now the core product question. Any future generator
must be able to say:

```text
no rendered handoff here
control is already enough
```

That behavior is now demonstrated in research as a judgment outcome. It is not
yet demonstrated as a generator/selective process. Generator implementation
therefore remains blocked.
