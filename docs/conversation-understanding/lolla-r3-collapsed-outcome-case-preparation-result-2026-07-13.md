## Plain-language outcome

The next R3 experiment is ready, but it has not run and cannot run from the
checked-in package alone.

We created one new 28-message simulated conversation about a small manufacturer
considering an anchor contract while capacity, household exposure, leadership,
customer mix, and succession concerns evolve. It is deliberately ambiguous:
the final answer is a conditional yes, not an obvious correct answer or a trap
designed to make Lolla win.

The repository now proves the order in which the test was designed:

1. The conversation was frozen before pressure models or expected results.
2. Six source-grounded reasoning patterns were mapped to existing canonical
   mental-model IDs, then the deterministic graph added three related models.
3. Only after those nine pressures were frozen did we write the hidden review
   contract.
4. Only after the hidden review was committed did we seal the request, budget,
   runner, and founder decision package.

That chronology matters. It prevents us from changing the conversation,
candidate set, or review target after seeing what the model says.

## What the test is trying to learn

The experiment asks one narrow question:

> Can Gemini 3.1 Flash-Lite process all nine intentionally noisy pressures in
> one fresh-context pass, return a mechanically coherent collapsed outcome for
> each, and produce source-grounded friction or restraint without bloating or
> damaging the useful original advice?

The previous R3 response contradicted itself because it expressed disposition
and effect in two separate labels. The selected contract now asks for one
controlled outcome such as `reject`, `park`, or `apply_new_condition`.
Deterministic code maps that explicit judgment to the canonical ledger; it does
not decide whether the pressure applies.

## What good looks like

First, the response must pass mechanical custody:

- exactly one row for each of the six direct and three graph pressures;
- exact pressure identity and order;
- source-turn custody and bounded text;
- a valid collapsed outcome with correct public/private effect custody;
- exact JSON with no repair;
- the pinned model and Google provider identity;
- provider response identity and exact reported cost within `$0.01`.

Only then is the hidden source review opened. A semantic signal requires at
least one non-forced source-grounded contribution or one valuable grounded
rejection while useful original advice survives. The recommendation does not
have to change. A graph pressure does not have to apply. Rejecting irrelevant
noise is part of the product behavior, not failure.

The protected review identifies three possible opportunity areas without
prescribing an answer:

- leading evidence that anchor priority is displacing custom work before
  surviving-customer metrics reveal it;
- a distinct pre-expiry recommitment condition, if the existing six- and
  twelve-month reviews do not already cover it;
- evidence that delegated commercial authority is real rather than meeting
  attendance, if the original answer has not already operationalized it.

It also records five strengths that pressure must not destroy and explicit
stand-down conditions for all nine mental models. The protected material is
hash-locked and absent from the provider request.

## Cost and operator decision

The exact frozen request estimates a maximum cost of `$0.00836875`. The hard
provider-reported ceiling is `$0.01`. It allows one call and no retry, fallback,
response healing, premium model, model switch, judge, or quiet control.

The dated current-practice check confirms that OpenRouter still lists Gemini
3.1 Flash-Lite at `$0.25` per million input tokens and `$1.50` per million
output tokens, and that the pinned structured-output and provider-routing
controls remain supported:

- [OpenRouter model pricing](https://openrouter.ai/google/gemini-3.1-flash-lite/pricing)
- [OpenRouter structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs)
- [OpenRouter provider routing](https://openrouter.ai/docs/guides/routing/provider-selection)
- [Google Gemini 3.1 Flash-Lite](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-lite)

The operator was not changed and no model comparison was run. Buying a more
expensive model would obscure whether the repaired interface—not extra model
capacity—solved the observed failure.

These are reliability and experimental-custody findings. They are not evidence
that a real provider response will be useful.

## Unknowns

Until the one call runs, we do not know:

- whether Google accepts this exact prospective request;
- whether the model returns a mechanically valid response;
- whether it uses exact source evidence instead of plausible business prose;
- whether it can stand down from already-covered or weak graph pressure;
- whether it finds useful friction without turning the answer into a checklist;
- whether one diagnostic result generalizes to other conversations or users.

One successful call would answer only the first version of those questions. It
would not prove product reliability, real-user usefulness, correct advice, or
the general value of graph expansion.

## Founder decision

The provider-free work is complete. The next action is one binary decision:

- **Authorize** one exact Gemini 3.1 Flash-Lite call with a hard `$0.01` ceiling.
  The first result is preserved and reviewed; there are no automatic follow-on
  calls.
- **Decline or defer** the call. The package remains reproducible, R3 stays
  empirically unresolved, and no money is spent.

The checked-in authorization file is intentionally only a non-authorizing
template. If the founder authorizes the call, that explicit decision must be
recorded in a separate exact authorization artifact before the runner can
