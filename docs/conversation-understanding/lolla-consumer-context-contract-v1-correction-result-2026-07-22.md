## Outcome

The six-output consumer-context design remains useful, but its claim boundary
is now narrower and more honest:

> It is a prospective, single-draw case diagnostic for an interaction between
> declared context representation and the complete fixed pressure package.
> It is not yet an executable causal-identification contract and cannot by
> itself prove same-context self-justification, graph-specific value, expected
> model behavior, human usefulness, or a production architecture.

The current machine boundary is
`docs/evals/lolla-consumer-context-pressure-ablation-contract-v1.json`. The
merged v0 contract remains its preserved prospective predecessor. V0 is not a
second current contract and was not rewritten.

## Why the correction was necessary

The v0 topology already avoided several naive mistakes: it had transcript-only
controls in both context modes, isolated treatment and control, held F3/T3
pressure bytes equal, allowed grounded rejection, treated higher uptake as
possible forced absorption, and authorized no execution.

However, the PRD and plan said the unexecuted design already “distinguished”
the mechanisms. Two fresh repository-only AI readers independently rejected
that stronger claim.

One reader focused on constitutional product evils. It found that:

- a fluent apply/reject/park ledger can hide semantic non-consideration;
- F2's direct content was not required to be identical to F3's direct
  component;
- hashes did not prove that every active planner candidate reached the
  presented payload exactly once;
- mandatory absorption can happen in T3 or F3, not only in fresh context;
- a completed-zero quiet case tests manufactured supply, not consumer
  absorption when no payload exists;
- the source-reviewed human condition needs exposure and uncertainty custody
  and must not be called an oracle.

The other reader focused on causal identification and implementation custody.
It found that:

- the repository has no complete, capturable, branchable pre-pressure host
  checkpoint;
- a checkpoint immediately before ordinary Step 6 is already exposed to
  pressure results and therefore cannot produce a valid T0;
- “trajectory” versus “fresh” changes roles, attribution, reconstruction,
  recency, token position, and possibly information or execution surface at
  once;
- one stochastic output per cell cannot separate an expected interaction from
  model-call variance;
- the subtraction operator was undefined for the non-scalar evidence vector;
- equal F3/T3 pressure bytes do not prove equality of the complete request
  envelopes;
- the existing validator proved declared topology, not execution readiness.

The collaboration service permitted two genuinely fresh review contexts in
this thread. A planned third independent implementation reader was blocked by
the four-agent thread limit. That lane was therefore inspected secondarily by
the causal reviewer and is not represented as a third independent opinion.
Neither review inherited the working conversation, inspected private sources,
acted as the principal human, edited files, or called a provider.

## What v1 changes

### 1. Truthful readiness

V1 exposes separate machine states:

```text
design_shape_valid = true
execution_ready = false
single_draw_evidence_class = single_draw_case_diagnostic
causal_interaction_identified = false
self_justification_mechanism_identified = false
```

A green structural validator now means that the prospective design retains its
six cells, boundaries, nonclaims, and missing prerequisites. It does not mean a
case can be executed.

### 2. Correct estimand

The primary comparison is now named
`consumer_context_representation_interaction`:

```text
(T3 - T0) - (F3 - F0)
```

The subtraction is not a scalar arithmetic operation. A principal human must
compare source-linked categories including new leverage, grounded rejection,
grounded park, circular restatement, forced absorption, unsupported claims,
preserved/lost value, burden, uncertainty, and disagreement.

An interaction can be consistent with coherence defense. It does not identify
that mechanism because role topology, attribution, reconstruction, tacit-
context loss, token load, generic augmentation, and stochastic variation remain
competing explanations.

### 3. One honest context implementation

Before a case can be frozen, the team must select exactly one implementation:

1. **True host-trajectory fork:** export and branch the complete host state
   before any experimental pressure exposure under the same model/interface
   envelope.
2. **Prompt-level role/attribution representation:** run all four core cells
   through the same endpoint, representing the prior answer as assistant-role
   history or attributed transcript evidence.

The second option tests representation and is not an exact live-host clone.
The first option is not currently implemented.

### 4. Exact pressure custody

V1 requires:

- byte-identical pressure content, order, formatting, and source-label
  visibility between F3 and T3;
- byte-identical direct candidate IDs, content, order, formatting, and labels
  between F2 and the direct component of F3;
- an exact one-to-one mapping from every active planner pressure ID to one
  presented pressure item, with no missing, extra, merged, or duplicated
  active candidate;
- complete serialized messages, roles, wrappers, schemas, pressure insertion
  points, token/fan-in counts, model/interface identity, and hashes per cell.

This prevents a future offline builder from recreating upstream probabilistic
re-domestication during payload serialization.

### 5. Human semantic boundary

The controlled packet is now a
`source_reviewed_human_controlled_reference_condition`, not an oracle. It must
record author, source set, authoring order, prior graph/model/output exposure,
corrections, uncertainty, and disagreement.

The new rejection-versus-coherence-defense rubric asks whether:

- the strongest plausible application was attempted;
- the failed condition is specific and source-supported;
- forcing harm is concrete;
- the rationale adds a source-grounded test rather than repeating the prior
  answer;
- a park condition is actionable and reopenable;
- semantic non-consideration laundering occurred;
- reviewer uncertainty and disagreement were preserved.

A complete ledger still proves only custody and declared rationale.

### 6. Symmetric absorption and quiet control

Mandatory-consideration absorption is now tested in both T3 and F3. Fresh-
context amplification remains a hypothesis rather than the definition of the
failure.

The quiet case is now a `supply_stand_down_negative_control`. If its source-
first condition is completed-zero, it tests whether the semantic supplier or
graph machinery manufactures pressure. With no pressure payload, it cannot
test consumer absorption. A known-weak pressure case would require a separate
future contract and authorization.

### 7. Stochastic and blinding boundary

One output per cell remains permissible only as a descriptive case diagnostic.
Any later causal claim requires demonstrated deterministic replay or separately
authorized prospective repeats with randomized or counterbalanced order.

The future review protocol must use anonymized, randomized output IDs, record
the evaluator's arm guess before reveal, and preserve the reveal time and all
disagreement.

## Verification

for:

- naive fresh-context and self-justification claims;
- false execution or causal readiness;
- sequential-session contamination;
- cell and paired-comparison drift;
- F3/T3 payload drift;
- F2/F3 direct-component drift;
- active-candidate/presented-payload custody loss;
- missing human rubric or false oracle status;
- quiet-case absorption overclaim;
- provider, runtime, or fresh-context-promotion authorization drift.
