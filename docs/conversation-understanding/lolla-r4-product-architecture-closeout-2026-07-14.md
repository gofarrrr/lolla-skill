## Executive result

The current incremental R4 residual reader architecture should stop. The final
A2 experiment showed that splitting the two surfaces into separate calls
preserved the genuine findings but did not remove unsupported companions, and
the separated dependency calls continued to misclassify governed machinery.
Another prompt, task-shape, holdout, or provider run is not earned.

This is not a decision to stop Lolla's conversation product. R4 tested one
prospective structured reader for unresolved matters and reopen conditions. It
did not replace or invalidate:

- complete available prose-conversation custody;
- the live four-lane reasoning-pressure path;
- the curated mental-model and relationship graph;
- deterministic graph-survival custody;
- apply, reject, or park reconsideration;
- archived process evidence;
- the optional Decision Work sidecar;
- the read-only Observatory.

The product objective also survives: preserve a consequential AI conversation,
introduce traceable pressure from outside its current reasoning trajectory,
record the reconsideration, and make the decision episode inspectable without
claiming that the machine certified a better answer.

## What A2 established

The canonical A2 result is
`separated_tasks_ineffective_companions_persist`:

- all twelve frozen calls completed exactly once;
- both genuine positive findings survived paired and separated generation;
- each paired positive call emitted an unsupported opposite-surface companion;
- each corresponding separated call emitted the same companion class;
- separated decision-gap calls returned correct zero on both quiet controls;
- separated dependency calls emitted governed-machinery false positives on
  both quiet controls;
- no retry, fallback, healing, substitution, evaluator, relationship, graph,
  pipeline, or runtime call occurred.

The exact provider-reported A2 cost was `$0.02148425`. The one-use
authorization is consumed. No further R4 provider execution is authorized.

A2 falsifies the tested claim that paired two-surface completion pressure was
the cause of the companion behavior. It also reinforces an independent
dependency-reader defect: operational thresholds, fallbacks, scheduled
governance, and present remediation work are too often converted into residual
future pressure.

## What A2 did not establish

A2 does not establish that:

- every conversation-understanding architecture must fail;
- the complete conversation is unusable;
- the mental-model graph path is broken;
- the four live pressure lanes are ineffective;
- the Decision Work sidecar has no product value;
- a stronger model would fix the failure;
- any current component improves real-user decisions;
- any reader or sidecar should be integrated automatically;
- a clean process receipt proves advice quality.

The four simulated cases were a bounded causal instrument, not real-user
product evidence.

## The architecture after R4

```text
complete available user/assistant prose conversation
                    |
                    +--> live pressure path
                    |      bounded extraction + complete captured turns
                    |      -> ConversationContext / ConversationIR
                    |      -> four pressure lanes
                    |      -> mental-model recall and graph survival
                    |      -> apply / reject / park reconsideration
                    |      -> revised answer, ledgers, memo, receipt
                    |
                    +--> completed-run archive
                           -> optional offline interpretation
                           -> Decision Work sidecar
                           -> read-only Observatory and portable views
```

The archive is the seam. The sidecar does not feed live mental-model selection,
graph traversal, or the revised answer. The live pressure path does not require
the sidecar. Observatory may read the base run and any sidecar that exists.

## Full-conversation invariant

`conversation.txt` remains the authoritative human-dialogue artifact. It
contains the complete available user and assistant prose captured for the run;
system messages, tool payloads, tool results, and file contents are outside the
current capture contract.

Every compact view or interpretation is derivative. In particular:

- `conversation_processing_view.txt` may omit middle turns for an extraction
  call when the source exceeds the current character bound;
- its metadata must declare that it is partial and non-authoritative;
- the live pipeline still receives the original conversation file and parses
  all captured turns;
- a sidecar or portable Markdown view may locate the private transcript rather
  than duplicate it;
- no summary may silently replace the source transcript;
- future product claims must distinguish source preservation from semantic
  comprehension.

The product value of keeping the conversation is not archival abundance. It is
the ability to inspect how the frame evolved, which user challenges mattered,
which assistant suggestions were adopted or rejected, what changed, and which
uncertainties survived.

## Live mental-model pressure boundary

The live model-companion path remains separate from R4. It builds an all-turn
lane packet, fingerprints the conversation, recalls from the curated substrate,
and freezes a bounded direct and graph-expanded portfolio before the legacy
probabilistic verifier. That verifier cannot delete the constitutional
portfolio. Every active item requires an apply, reject, or park disposition.

This path works mechanically. That statement means the code runs, preserves
canonical identity and provenance, bounds the portfolio, and records
dispositions. It does not mean that the selected pressure is semantically
optimal or that it improves a real user's decision. Those remain R5-style
product questions and are not authorized by this closeout.

The live path also does not yet reconstruct the entire interaction trajectory.
Although all captured turns are available, the current extraction is one
decision situation, one latest synthesized position, a small passage set,
constraints, framing, and dropped threads. It cannot be treated as a reliable
account of every challenge, concession, adoption, reintroduction, or parallel
thread in a long conversation.

## Decision Work sidecar boundary

Decision Work is the post-run interpretation and presentation layer, not a
second reasoning engine. Its intended value is to let a later person or agent
understand:

- what the conversation was trying to decide or understand;
- how framing, options, constraints, and likely actions evolved;
- what the user challenged, adopted, rejected, or deferred;
- what Lolla pressed on and how that pressure was disposed;
- what changed in the revised answer;
- what remains unknown or unresolved;
- which source, uncertainty, privacy, and human-review limits apply.

The current sidecar can validate supplied interpretation artifacts, render a
brief, prepare triage and resolver candidates, preview an explicit write, and
write a bounded file set through a confirmed no-overwrite operator path. The
post-archive hook is default-off. Observatory reads sidecar status and content
without generating interpretation or mutating the run.

What is missing is a trustworthy automatic semantic read for arbitrary
completed conversations. The offline queue and operator runner organize
metadata and supplied reads; they do not create meaning. R4 must not be wired in
as that missing generator merely because the packaging path exists.

## Product interpretation

The project contains three distinct value propositions:

1. **Pressure now.** Before the human acts, expose a traceable alternative
   lens, failure condition, frame, trade-off, or question and require an honest
   disposition.
2. **Understand later.** Preserve a source-grounded Decision Trail so a later
   person or agent can understand how the conversation and action changed.
3. **Inspect the process.** Use Observatory and portable artifacts to navigate
   evidence, states, costs, pressures, dispositions, omissions, and non-claims.

These propositions reinforce one another but require separate evidence. A
useful sidecar would not prove that the pressure improved the answer. A useful
pressure item would not prove that the sidecar reconstructed the conversation.
A mechanically complete run would prove neither.

The appropriate product language remains: Lolla makes another angle and the
process around it inspectable before the human decides. It does not grade the
conversation with one score, certify reasoning quality, or replace human
authority.

## Why the current R4 reader stops

The program has already tested:

- a complementary reader;
- semantic-boundary wording;
- a residual-discovery task identity;
- leakage-corrected matched evidence;
- a causal diagnosis;
- paired versus separated task shape;
- two terminal executions of the separated design, with A2 complete.

The same central restraint problem survived meaningful changes. Continuing
with another warning, example, schema arrangement, retry, or simulated holdout
would no longer be a disciplined causal step. A future semantic reader would
need a materially different architecture and a new founder decision.

## Ordered next work

### Next eligible goal: completed-run artifact-to-Decision-Trail coverage audit

The next goal should remain provider-free. It should inspect the current run
archive, Decision Work contracts, sidecar machinery, and Observatory against
one or more existing completed runs and produce a field-level coverage matrix.

For every desired Decision Trail field, classify it as:

- deterministically available from existing artifacts;
- available only as a provisional LLM or human interpretation;
- requires explicit human review;
- unavailable from current artifacts;
- intentionally private or locator-only;
- unsafe to expose or use for action.

The audit must include user challenges, assistant influence, user adoption or
rejection, changes of mind, option history, constraints, unknowns, pressure
dispositions, answer changes, missingness, and source custody. It should also
show exactly what the current sidecar and Observatory can render when semantic
input is present, absent, deferred, blocked, or failed.

It should not generate a new semantic read, call a model, write into a real
archive, change runtime, or claim usefulness. Its decision is whether the next
value test should use the current operator-assisted sidecar, simplify it, or
design a materially different human-correctable whole-conversation reader.

### Later gates

Only after that coverage audit should the founder consider:

1. a small human product review of an operator-assisted Decision Trail built
   from a genuine completed conversation;
2. a materially different offline whole-conversation reader if the missing
   semantic fields prove essential;
3. R5-style comparison of the live pressure path against a strong neutral
   control and cold-reader receipt reconstruction;
4. any broader memory, Teacher, model comparison, runtime integration, or
   productization work.

None of those later gates is authorized by this closeout.
