## Architectural decisions

- **Current product promise:** pressure-now means preserve, pressure,
  reconsider, disposition, and process receipt. It does not promise reliable
  longitudinal understanding or a better answer.
- **Separate evidence lanes:** PR104 human semantic correction, graph
  contribution, answer value, and checked-in-safe interface truthfulness never
  validate one another by proxy.
- **Source authority:** complete available conversation prose or an exact
  frozen case source remains authoritative. Every semantic packet declares its
  processing view and omissions.
- **Semantic authority:** LLM and human interpretations remain provisional or
  human-corrected. Deterministic code verifies custody and bounds only.
- **Graph ownership:** reuse the repository's compiler, immutable published
  reader, `ReasoningPatternPacket` boundary, reasoning-mechanism ontology, and
  constitutional pressure planner. Do not add parallel owners.
- **Current graph policy:** direct-active seeds, authored outgoing direction,
  one hop, antagonist/tension/ally slots, deterministic active/reserve custody.
- **Evaluation arms:** transcript-only, current live bridge plus current graph,
  human-controlled direct-only, and the same human-controlled input plus the
  current graph. Run these four graph-supply arms in fresh reconstructions;
  add two cloned-trajectory outputs for transcript-only and fair graph pressure
  so the context-by-pressure interaction is observable without an eight-cell
  bundle.
- **Consumer-context authority:** ordinary live Step 6 is same-context and
  observational. A fresh reconstruction is a control condition, not an
  independent truth source or an automatically better runtime.
- **Evidence model:** retain source fidelity, semantic behavior, graph custody,
  unique pressure, forced association, cognitive load, dispositions, answer
  integrity, lost value, human burden, privacy, and cost separately.
- **Artifact policy:** write prospective results beside frozen evidence. Never
  fill PR104 or rewrite R4/minimum-loop artifacts in place.
- **Authorization:** provider-free fixtures and validation do not authorize a
  human review, provider call, graph change, runtime promotion, or product
  claim.

## Phase 2: Complete One Source-First PR104 Human Review Slice

**User stories**: A principal human can review one June candidate read from
source, correct or reject it, and show which semantic fields are useful or
unavailable without altering the historical intake.

### What to build

For exactly one PR104 case, freeze the source set and reviewer identity. Create
a prospective human-review record that reads source before the candidate
interpretation and captures corrected decision question, vanilla overlap,
action delta, preserved/lost value, candidate errors, useful fields,
simplification requests, unavailable source, and a non-scalar net read. If the
required private source is unavailable, produce a signed unavailable result
and stop the phase.

### Acceptance criteria

- [ ] One exact case and source set are named and hash-locked.
- [ ] The reviewer is a principal human, not Codex, a provider judge, or a
      maintainer acting without source authority.
- [ ] Source is reviewed before the candidate read, or the result is explicitly
      unavailable.
- [ ] Corrections and preserved/lost value remain separate from custody.
- [ ] The historical PR104 packet and all blank fields remain byte-unchanged.
- [ ] No fourth specialist pilot, broad batch, R4 reader, provider call,
      automatic label, or agent authority is introduced.

## Phase 3: Build One Provider-Free Conversation-to-Graph Custody Slice

**User stories**: An evaluator can take one existing checked-in-safe realistic
case from authoritative source through a supplied source-reviewed mechanism
packet and the current graph planner, then inspect the four graph-supply arms,
the two additional trajectory-continuation outputs, and every missing
component without a provider call.

### What to build

Freeze one existing useful-pressure development case with source, source-first
target, supplied fact-free mechanism packet, graph release, current policy,
direct candidates, one-hop paths, active/reserve dispositions, named arm
contracts, a pre-pressure context-checkpoint manifest, exact context-mode
representations, expected output locations, and human rubric. Reuse checked-in
historical outputs where they exactly match; mark every unavailable new output
as missing instead of simulating it. Produce request previews only for any
future reasoner/provider work. Use
`docs/evals/lolla-consumer-context-pressure-ablation-contract-v0.json` as the
machine boundary.

### Acceptance criteria

- [ ] One realistic multi-turn source and every input hash are frozen.
- [ ] The human/source-reviewed packet contains controlled mechanisms only;
      raw case facts, graph model names, desired outcomes, and topic labels do
      not enter routing.
- [ ] Current direct and one-hop graph portfolios replay against the named
      substrate and policy identities.
- [ ] Transcript-only, current-live, human-direct-only, and human-current-graph
      arms have exact fresh-reconstruction contracts even when an output is
      unavailable.
- [ ] Transcript-only and human-current-graph also have exact isolated
      trajectory-continuation contracts cloned from one pre-pressure
      checkpoint; neither continuation sees the other's output.
- [ ] F3 and T3 use byte-identical pressure content, order, formatting, and
      source-label visibility; any mismatch makes the context comparison
      noncausal.
- [ ] The packet distinguishes complete, completed-zero, partial, failed, and
      missing per arm.
- [ ] No provider or embedding call, runtime import, receipt promotion, or
      semantic repair occurs.

## Phase 4: Run One Authorized Useful-Pressure Comparison

**User stories**: A source-first human can tell whether the current graph adds
a material angle and whether any defect belongs to the semantic bridge, direct
recall, relationship expansion, or the reasoner.

### What to build

After a separate exact provider/human authorization, execute the frozen six
outputs once with no automatic retries or fallbacks. F0–F3 are the four
fresh-reconstruction graph-supply arms. T0 and T3 are isolated continuations
of the same pre-pressure trajectory for transcript-only and fair graph
pressure. Preserve first terminal results, complete context/provider/cost/
privacy custody, all pressure dispositions, and a source-first non-scalar
human comparison. Do not tune prompts or policy after seeing an output.

### Acceptance criteria

- [ ] Authorization names the exact case, prompts, schemas, routes/models,
      seeds, call cap, output caps, USD ceiling, privacy treatment, retry rule,
      and stop conditions.
- [ ] Every output uses the same authoritative source, declared model envelope,
      and exact context-mode representation; model or payload drift is
      preserved as a confound rather than repaired.
- [ ] F1 versus F3 isolates semantic supply; F2 versus F3 isolates graph
      expansion; F0 versus F3 isolates fresh graph-backed pressure.
- [ ] T0 versus T3 isolates trajectory-continuation pressure; comparing that
      delta with F0 versus F3 tests context interaction rather than raw uptake.
- [ ] A lower apply rate is not called domestication without circular or
      non-grounded treatment; a higher apply rate is not called success when it
      creates forced absorption, lost value, bloat, or false precision.
- [ ] Human review records useful pressure, forced association, cognitive load,
      answer integrity, preserved/lost value, and correction burden separately.
- [ ] No scalar winner or automatic promotion is produced.
- [ ] Invented high-stakes facts or causation stop the case without a retry.

## Phase 5: Repeat the Exact Contract on One Quiet Stand-Down Case

**User stories**: A user with an already adequate decision can receive no
graph pressure without the system manufacturing a problem or bloating the
answer.

### What to build

Freeze one realistic quiet case and execute the same six-output nested contract
under a new exact authorization. The semantic target must permit completed-zero
mechanisms and the planner/evaluator must preserve an honest stand-down. Review
whether any output invents a weakness, forces graph use, or adds public
friction, and whether fresh reconstruction increases absorption merely because
pressure was selected.

### Acceptance criteria

- [ ] The case has a source-first target that permits no unresolved mechanism.
- [ ] Completed-zero is distinct from missing, failed, or partial.
- [ ] No graph traversal or reasoner call occurs when the frozen contract says
      the arm is a completed-zero stand-down.
- [ ] Any manufactured mechanism, graph candidate, or public pressure is
      recorded as a failure, not a richer answer.
- [ ] The useful and quiet cases retain separate evidence and costs.
- [ ] No graph or runtime promotion follows automatically.

## Phase 6: Test One Graph Alternative Only If a Specific Miss Is Proven

**User stories**: An evaluator can test one evidence-backed graph hypothesis
without turning all 222 models into a near-universal neighborhood or rewriting
the current policy.

### What to build

If Phases 4–5 establish one named useful lens missed under a fair semantic
input, freeze exactly one candidate policy: incoming-reference traversal,
direct-reserve expansion, or bounded two-edge outgoing traversal. Version it
prospectively and compare it with the unchanged current planner on the exact
miss case plus the quiet control.

### Acceptance criteria

- [ ] The prior result names the exact miss and why the current policy caused
      it.
- [ ] Exactly one direction/seed/depth change is admitted.
- [ ] Candidate volume, order, deduplication, active/reserve bounds, path
      custody, and truncation behavior are frozen.
- [ ] Incoming references retain authored direction; paths do not become new
      relations or transitive truth.
- [ ] The quiet case guards against expansion-induced false pressure.
- [ ] The candidate policy remains offline and cannot overwrite V1 or enter
      the live reasoner/receipt.

## Phase 7: Make One Product Architecture Decision

**User stories**: The founder can choose one coherent product based on human
evidence rather than artifact volume: pressure-now, understand-later,
pressure-plus-correctable-memory, or a deliberate stop.

### What to build

Synthesize PR104 human correction, useful and quiet graph comparisons, answer
integrity, privacy/cost, and correction burden without combining them into a
score. Decide which components earned further investment. Only then write a
separate runtime or product implementation PRD.

### Acceptance criteria

- [ ] Mechanical, semantic, graph-specific, answer-level, human-usefulness,
      privacy, cost, and market hypotheses remain separate.
- [ ] The decision names which user job is primary and which components remain
      bounded, parked, retired, or removed.
- [ ] A graph contribution is not inferred from reachability or path count.
- [ ] A semantic-understanding claim is not inferred from truthful labels.
- [ ] A better-answer claim is not inferred from apply/reject/park custody.
- [ ] Any live implementation starts only from a new approved PRD with
      rollback and evidence gates.

## Stop rules for the whole plan

Stop and preserve the current boundary when:

- no principal human/source capacity exists for Phase 2;
- a case cannot be evaluated without private data outside its consent plan;
- the semantic target is disputed or unavailable;
- graph arms add no unique value or create forced association/friction;
- a provider contract is missing any route, budget, privacy, retry, or stop
  field;
- a pre-pressure checkpoint cannot be captured honestly, control and treatment
  cannot be isolated, or source-label/payload differences confound context;
- work would require R4 revival, automatic Decision Work semantics, Atlas or
  interface expansion, or runtime mutation to make an evaluation look clean.

“No evidence yet” is a valid state. It is not permission to build more
machinery.
