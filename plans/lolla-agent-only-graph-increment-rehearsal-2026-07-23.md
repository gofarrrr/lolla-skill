# Agent-only graph-increment rehearsal plan

Date: 2026-07-23

Status: prospective provider-free contract; freeze before agent outputs

Owner: existing offline Product Delta evaluation

Provider/API calls authorized: 0

Graph, planner, compiler, runtime, skill, and interface changes authorized: none

## Founder decision

The founder does not want to participate as a source-first reviewer or output
labeler. The existing principal-human consumer-context experiment therefore
remains unfilled and paused. Agent output must not be written into its blank
human target or presented as equivalent evidence.

The authorized continuation is a separate **evidence class**, not a separate
product:

> Automate a checked-in-safe development rehearsal inside Product Delta, label
> every semantic judgment as an agent proxy, and test the current direct-only
> versus direct-plus-one-hop-graph difference without making a human-usefulness,
> provider, causal, model-performance, or runtime claim.

## Falsifiable question

> In one retrospective retailer case, what source-reviewable reasoning
> difference appears between an isolated direct-only rehearsal and an isolated
> direct-plus-current-one-hop-graph rehearsal, and can blind fresh-agent
> reviewers distinguish new leverage from repetition, forced association,
> lost value, unsupported content, and burden without choosing a winner?

An answer of “no material difference,” “the graph only added burden,”
“generation failed,” or “reviewers disagree” is allowed.

## Why this does not complete the human experiment

The principal-human experiment asks whether another angle helps a person make a
real decision. An agent can inspect source consistency and reasoning structure,
but it cannot report another person's `aha`, correction burden, trust, or
decision consequences.

The automated rehearsal instead asks whether the machinery and current graph
increment produce an inspectable difference under controlled checked-in
inputs. Its result may improve experiment design or justify standing down. It
cannot validate the product promise.

## Frozen experimental slice

Only one comparison enters this rehearsal. The generated arms are named
`rehearsal_direct` and `rehearsal_direct_plus_current_one_hop`. F2 and F3 are
lineage references to frozen provider-neutral previews, not names for realized
outputs:

```text
rehearsal_direct
  checked-in complete source
  + historical source-review projection
  + exact messages/schema inherited from the F2 direct-only preview

versus

rehearsal_direct_plus_current_one_hop
  the same checked-in complete source
  + the same byte-identical direct component
  + exact messages/schema inherited from the F3 preview
  + the existing current outgoing one-hop graph increment
```

The graph increment is limited to the already frozen current projection. The
rehearsal does not add incoming traversal, reserve expansion, a second hop,
community search, graph mutation, embeddings, or a database.

F0, F1, T0, and T3 remain outside this slice. Therefore this rehearsal does not
test the current live semantic bridge, same-context reconsideration,
trajectory representation, or consumer-context interaction.

## Stage 1 — source-only agent proxy reads

Two isolated fresh agents receive only the authoritative source and the frozen
source-only response contract. They do not receive candidate identities,
relations, historical targets, prior generated outputs, request previews, or
each other's work.

Each records:

- the current decision or position;
- strong reasoning that should survive;
- unresolved questions;
- what would be genuinely new leverage;
- what would be circular restatement;
- what would be forced absorption or harm;
- uncertainty and alternative readings.

These are `fresh_agent_source_first_proxy` reads. They are not targets,
signatures, human corrections, ground truth, routing authority, or an oracle.

Both artifacts and hashes must exist before Stage 2.

## Stage 2 — post-seal reference-condition review

After its source-only target is frozen, each source-first agent receives:

- its own exact frozen target;
- the historical direct reference condition;
- the condition's prior-exposure warning.

It may record source consistency, partial consistency, a source tension, or
uncertainty for each direct candidate. These are observations, not approval or
rejection authority. Corrections and disagreement remain review observations;
they do not silently delete, replace, or rerank candidates for this rehearsal.

That rule is constitutional: an agent proxy must not domesticate the current
graph condition by rewriting it after seeing the source.

## Stage 3 — isolated generation rehearsal

Two new isolated fresh agents each receive exactly one neutrally aliased
generation packet:

- one contains the exact checked-in F2 messages and schema;
- one contains the exact checked-in F3 messages and schema.

The mapping is deterministic and sealed. Each agent sees no sibling packet,
lineage, target reviews, historical result, or other generated answer.

This is a Codex-assisted development rehearsal. Six fresh collaboration-agent
contexts are predeclared: two source-first contexts with post-seal follow-up,
two isolated generation contexts, and two blind review contexts. It is not
execution through a frozen provider/model interface:

- repository provider calls remain zero;
- the ambient platform system/developer context remains present, so the agents
  do not literally execute a standalone three-message provider envelope;
- the exact task wrapper and inherited preview are hashed separately;
- the underlying platform model, route, token usage, and economic cost are
  unavailable to the repository operator and must not be reported as zero;
- no model identity, seed, temperature, or tokenizer contract is inferred;
- one output per arm is a single draw;
- the first terminal response is preserved;
- no automatic retry, healing, fallback, or replacement is permitted;
- schema or exact-candidate-set failure stops that arm.

## Stage 4 — blind Product Delta review

The two terminal outputs are anonymized and deterministically ordered. Two new
fresh reviewers receive:

- the complete authoritative source;
- the two anonymized outputs;
- the existing reviewer qualification traps, duplicate null, and quiet
  stand-down controls;
- the frozen atomic-move and non-scalar review contract.

They do not receive lineage, candidate origin, the sealed manifest, source
proxy outputs, or each other's review before freeze.

They record:

- genuinely new source-grounded leverage;
- grounded rejection or park behavior;
- repetition and circular restatement;
- forced absorption;
- unsupported facts, causation, or precision;
- preserved and lost original value;
- friction and cognitive burden;
- uncertainty;
- an arm-origin guess only after substantive review.

No winner, score, rank, vote, certification, or automatic policy decision is
allowed.

## Stage 5 — deterministic consolidation

After all reviews are frozen, deterministic code may reveal:

- which alias was F2 and which was F3;
- exact request, response, source, candidate, graph, policy, and artifact
  hashes;
- schema and candidate-ID validation state;
- reviewer agreement and disagreement;
- source-proxy reference-condition observations.

It may not decide which reviewer is correct or convert agreement into
authority.

## Decision meanings

| Observation | Bounded meaning | Allowed next move |
| --- | --- | --- |
| The two rehearsal arms are materially indistinguishable | No graph-increment difference observed in this rehearsal | Preserve direct-only and stand-down as live possibilities |
| The graph-lineage rehearsal adds a source-grounded falsifier, option, or evidence gate without material loss | One Codex-assisted simulation produced a case-specific useful difference | Repeat only under a separately frozen diverse or quiet case |
| The graph-lineage rehearsal adds only repetition, generic caution, unsupported claims, or burden | The current increment did not earn its burden in this simulation | Do not expand traversal; inspect the exact paths |
| The graph-lineage rehearsal loses strong existing reasoning | Mandatory-pressure absorption or answer-integrity risk | Preserve failure; do not retry to obtain a cleaner answer |
| Reviewers disagree | Semantic result remains ambiguous | Preserve disagreement; do not vote |
| Either arm fails terminal schema/custody | Rehearsal is not evaluable | Stop without replacement |

None of these observations changes the live graph or authorizes provider work.

## Stop rules

Stop before:

- filling any principal-human field with agent output;
- rewriting frozen consumer-context v1 or its blank target;
- exposing graph candidates before source-only proxy targets are frozen;
- letting proxy judgments silently remove candidates;
- executing mismatched direct components;
- adding any graph increment beyond the frozen current one-hop projection;
- retrying or healing a terminal generation;
- revealing lineage before paired reviews are frozen;
- ranking, scoring, voting, or selecting an answer;
- claiming human usefulness, causal graph value, expected model behavior, or
  production readiness;
- calling the agent sessions economically free or reporting unavailable
  platform route, token, or cost custody as zero;
- any provider/API call, private archive access, live-skill invocation, graph
  change, runtime change, or interface work.
