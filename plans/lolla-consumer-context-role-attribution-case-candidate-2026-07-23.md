## Gated continuation

### Gate 1 — principal-human source-first target

Owner: principal human.

The reviewer opens only the authoritative source and blank target template.
Before seeing candidate identities, graph paths, prior outputs, or request
previews, the reviewer records:

- the current decision or position;
- strong original reasoning that must survive;
- unresolved questions;
- what would count as new leverage;
- what would count as circular restatement;
- what would count as forced absorption or harm;
- uncertainty and alternative readings.

The target is signed and sealed before reference-candidate disclosure.

Exit condition: a signed source-first target exists and the reviewer has
approved, corrected, or rejected the proposed reference condition. A blank or
AI-filled form does not pass.

### Gate 2 — exact F1 current-live semantic supply

Owner: founder and a separately authorized execution operator.

Research the then-current official provider/model guidance, freeze the exact
current live semantic-bridge contract for this source, and determine the exact
provider calls required. Do not reuse R4 or an older mechanism reader. Preserve
the first terminal result and its missing/partial/failed state.

Exit condition: F1 has an exact, source-custodied current-live bridge supply or
the six-cell execution is stopped.

### Gate 3 — provider contract and request freeze

Owner: founder and execution operator.

Freeze:

- provider, model, interface, route, privacy policy, and model identity;
- exact message arrays and response schemas;
- temperature, top-p, seed behavior, output cap, and tokenizer counts;
- cell order, isolation, drift recording, and stop rules;
- maximum semantic-supply and six output calls;
- exact USD ceiling;
- no retry, fallback, healing, replacement, evaluator call, or model
  substitution.

Exit condition: every request is executable and hash-locked, with an explicit
founder authorization matching the exact call and cost envelope.

### Gate 4 — isolated single-draw execution

Owner: authorized execution operator.

Run cells in the predeclared order and in isolated contexts. Preserve the first
terminal result of each authorized call. One output per cell remains a
single-draw case diagnostic.

Exit condition: terminal output, request/response/usage/cost custody, and
provider drift identity exist for every authorized cell. Any schema, custody,
privacy, or answer-integrity failure stops the run.

### Gate 5 — blinded non-scalar review

Owner: principal human; alias mapping held by a nonreviewing operator.

Commit the hidden alias mapping before review. Present randomized anonymized
outputs. Record the reviewer's arm guess before reveal. Compare source-linked
differences across the predeclared categories without a winner score.

Exit condition: the reviewer has recorded candidate treatment, answer-level
preservation/loss, unsupported content, forced absorption, friction, and
uncertainty, then the alias mapping is revealed.

### Gate 6 — decision

Owner: founder.

Allowed decisions include:

- the case is not evaluable;
- no context interaction is visible;
- the result is mechanism-consistent but noncausal;
- fresh representation over-absorbs pressure;
- trajectory representation appears circular;
- graph pressure adds no distinct value;
- the F1 bridge is the case-specific defect candidate;
- a repeated or placebo-controlled experiment may be worth a new contract.

No one-case result authorizes a live context switch, traversal change,
production claim, or scalar quality score.
