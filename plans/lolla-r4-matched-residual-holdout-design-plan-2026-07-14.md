## Falsifiable question

On the same genuinely new hidden long-form conversation evidence, does the
residual-task contract improve Case-04-style false-positive restraint over the
frozen v2 semantic-distinction contract while preserving Case-01-style
sensitivity to materially distinct residuals?

This plan designs and freezes a matched experiment. It does not execute the
experiment or establish that either contract is semantically successful.

## Fixed design

The four cases are:

- oral-history archive release governance, a governed-pending control whose
  prior uses broad unresolved language;
- an independent press's serialized-audio pilot, a governed-pending control
  without a matching prior gap anchor;
- research-data workspace stewardship, with a genuine recurring ownership,
  capacity, and funding residual outside temporary launch machinery;
- a cross-campus language program, with a genuine later accreditation-style
  dependency failure outside current safeguards and review machinery.

Every source contains 28 alternating messages, multiple threads, revisions,
qualifications, realistic ambiguity, and decision-relevant evidence in late
messages. They are simulated reliability evidence, not real-user evidence.

Arm A is the exact frozen v2 semantic-distinction contract. Arm B is the exact
residual-task contract introduced by the authorized residual repair. The only
provider-visible differences are the already-declared semantic-task identity
intervention: role, task operation, surface vocabulary, schema name and
semantic descriptions, examples, evidence wording, and output rules.

## Execution and budget boundary

The frozen prospective maximum is eight calls: four cases by two arms. Arm
order is counterbalanced and fixed before execution. The operator remains
`google/gemini-3.1-flash-lite` through `google-vertex` on OpenRouter, with
fallbacks off, required parameters, data collection denied, ZDR required,
strict JSON, non-streaming transport, one matched seed per case, minimal
reasoning with returned reasoning excluded, and a 1,600-token output cap.

At the official prices checked on 2026-07-14—`$0.25` per million input tokens
and `$1.50` per million output tokens—the conservative full-allocation estimate
is `$0.0424625`. A possible future execution would be bounded at `$0.015` per
matched case and `$0.06` total. These are frozen proposals, not authorization.

There are no relationship, evaluator, embedding, graph, pipeline, or runtime
calls; no retry, semantic retry, fallback, response healing, or model
substitution; and no deterministic semantic classification.

## Stop rules

Stop rather than broaden if matched custody requires different source, prior,
order, operator, seed, reasoning, or output allocation; if the task must be
split; if governed-pending must become a provider output; if relationship or
runtime behavior must change; if protected review evidence becomes runner-
accessible; if deterministic code must infer operationalization; or if a
provider call is needed to finish preparation.

No stop rule was triggered.
