# Conversation-state extraction experiment program

Status: active; founder delegated bounded experiment management  
Date: 2026-07-11

## Terminal question

Can three narrow probabilistic readers reliably populate Lolla's conversation-
state candidates while deterministic code owns source custody, validation,
candidate-state preservation, quarantine, and composition?

The program ends only with one of two conclusions:

1. **viable for the next system layer** — cross-case evidence meets the frozen
   semantic and custody requirements; or
2. **material redesign required** — the same important failures persist after
   bounded evidence-backed repairs, or the transport path cannot reliably reach
   inference.

## Program envelope

- development corpus only; no clean-holdout or product-effect claim;
- at most 12 new provider calls after this program was delegated;
- at most 3 calls per case, one per microtask;
- estimated program cost ceiling: $0.08;
- temperature 0, reasoning disabled, no automatic retry;
- no evaluator, graph, full pipeline, downstream answer, or runtime call;
- every operational and semantic failure preserved;
- no response healing, silent ID normalization, or post-hoc candidate repair;
- provider-free changes only between prospectively frozen stages;
- at most one semantic prompt-repair round before transfer determines whether
  material redesign is required.

## Transport decision

Strict OpenRouter-to-Google schema enforcement is closed after two thread-schema
HTTP 400 failures. The next stage uses `json_object` transport, includes the
exact typed schema in the prompt, and retains unchanged local typed parsing,
exact source resolution, candidate ledger, quarantine, and composition gates.
Provider syntax enforcement is not an admission gate.

## Frozen success requirements

Evidence must cover at least three completed development cases. Every counted
case must have all three families observed and mechanically reviewable.

### Positions and decision state

- supported decision summary;
- focal current position present without fragmenting its qualifications;
- reviewed ownership matches;
- material user and assistant late-turn contributions represented;
- zero source-custody violations.

### Focal threads

- reviewed focal thread present;
- reviewed full-trajectory disposition matches;
- no false `genuinely_dropped` classification;
- introduction, material response, and latest state preserved;
- zero source-custody violations.

### Atomic constraints

- atomic claims only; no `mixed` output;
- zero material source-strength inflation;
- source-reviewed precision at least 0.80 per case;
- source-reviewed recall at least 0.75 per case;
- zero source-custody violations.

### Composition

- all proposed candidates receive terminal ledger custody;
- invalid candidates never receive an event snapshot or accepted path;
- compiled handoff validates against source;
- zero direct graph seeds;
- absence and ambiguity remain valid observed outcomes.

## Redesign stop criteria

Conclude that material redesign is required if any occurs:

- JSON mode fails operationally on two prospectively frozen first-family calls;
- after one generic provider-free semantic repair, the same load-bearing
  ownership, trajectory, or source-strength failure recurs on two transfer
  cases;
- no three cases can meet every family gate within 12 calls or $0.08;
- passing requires silent correction, case-specific prompts, deterministic
  semantic relevance gates, retries, or weakened scoring thresholds.

## Stage sequence

1. Case 05 JSON-mode mechanical and semantic baseline: threads, constraints,
   positions.
2. Source-first review and, only if warranted, one generic provider-free repair.
3. Prospective transfer on cases not used to author that repair.
4. Cross-case reliability and composition conclusion.
